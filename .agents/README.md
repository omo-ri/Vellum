## 为什么进版本库

这些技能决定了 agent 在本仓库里怎么工作（怎么写 spec、怎么开工单、怎么做 code review）。把它们钉死在仓库里，是为了让 agent 的行为随代码一起被版本化——今天的提交和三个月后的提交，用的是同一套规则。

`../skills-lock.json` 记录每个技能的来源路径与内容哈希，是它们的溯源与完整性凭据。它记的是**出处**，署名与许可则由本目录的 `LICENSE` 承担——两者不能互相替代。

## 边界

- **上游的内容一律不改。** 需要项目特有的约定，写在 `docs/agents/` 下（那些是本项目自己的文件），或者写在技能引用的项目文档里。就地改上游文件会让内容哈希失配，也会在下一次同步时被覆盖。
- `../.claude/skills/` 是指向本目录的符号链接，由安装流程生成，不进版本库（见 `.gitignore`）。

MIT 只要求保留版权声明与许可声明，不要求本项目也采用 MIT——Vellum 自身的许可与这里无关。
